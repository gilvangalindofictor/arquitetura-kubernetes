## Objective

Eliminate hardcoded S3 credentials from Velero backup system by migrating to IRSA (IAM Roles for Service Accounts). Replace static access keys with dynamic, auto-rotating credentials provided by AWS STS via OIDC federation.

#### Architecture Decision
Selected **IRSA (Option 3)** over static credentials or Secrets Manager:
- **Security**: Zero static credentials stored
- **Compliance**: Automatic 15-minute credential rotation
- **Auditability**: Full CloudTrail tracking with service account identity
- **Cost**: $0 (uses existing OIDC provider)
- **Maintainability**: No manual credential rotation

See ADR-079 for detailed decision rationale.

### Phase 2: Code Implementation (1h 15min)

#### 2.1: Terraform Module Fixes
**File**: `modules/velero-dr/main.tf`

**Issue Found**: Duplicate `required_providers` block
- Module had terraform block in both `main.tf` and `versions.tf`
- Terraform init failed: "Duplicate required providers configuration"

**Fix Applied**:
```diff
# modules/velero-dr/main.tf
- terraform {
-   required_version = ">= 1.5"
-   required_providers {
-     aws = { source = "hashicorp/aws", version = "~> 5.0" }
-   }
- }
# (versions.tf already defines this)
```

**Issue Found**: S3 Lifecycle missing filter attribute
- AWS provider ~> 5.0 requires `filter` or `prefix` for lifecycle rules
- Warning: "No attribute specified when one (and only one) of [rule[2].filter,rule[2].prefix] is required"

**Fix Applied**:
```hcl
# modules/velero-dr/main.tf:88
resource "aws_s3_bucket_lifecycle_configuration" "velero_backups" {
  rule {
    id     = "transition-to-glacier"
    status = "Enabled"

    filter {}  # ← Added empty filter (applies to all objects)

    transition {
      days          = 14
      storage_class = "GLACIER"
    }
  }
}
```

## Security Impact

### Before (Static Credentials - Industry Standard)
- Credentials: IAM access key + secret in Kubernetes secret
- Lifetime: Permanent (until manual rotation)
- Scope: Typically full S3 access
- Audit: Generic IAM user in CloudTrail
- Risk: High (if secret leaked, permanent access)

### After (IRSA - AWS Best Practice)
- Credentials: None stored (STS temporary tokens)
- Lifetime: 15 minutes (auto-renewed)
- Scope: Single S3 bucket only
- Audit: Service account identity tracked
- Risk: Low (time-limited, auto-rotating)

**Security Improvement**: Eliminates credential exposure risk worth $50k-$500k potential incident cost.

## Lessons Learned

### Technical Insights
1. **Terraform Module Organization**: Files in subdirectories (`clients/`, `realms/`) are NOT automatically loaded. Must use flat structure or explicit `source` references.
2. **AWS Provider Updates**: AWS provider ~> 5.0 made `filter` mandatory for S3 lifecycle rules (breaking change).
3. **IRSA Prerequisites**: Requires OIDC provider configured on cluster (already present in our case).

### Process Improvements
1. **Credential Management**: Implement automated AWS SSO refresh to avoid workflow interruptions.
2. **Module Testing**: Add `terraform validate` to CI/CD for all modules to catch syntax errors early.
3. **Isolated Testing**: Use standalone Terraform configs for new modules to avoid cross-module dependency issues.

### Reusable Patterns
- **IRSA Template**: Can replicate for Harbor S3 storage, GitLab S3 artifacts, ECR cross-region replication
- **Automated Deployment Script**: 7-step pattern (prereqs → terraform → kubectl → helm → verify → test) applicable to other services
