## Lições Aprendidas

### 1. Baseline já existente acelerou trabalho
- **Problema:** Estimativa original assumia stack do zero
- **Realidade:** 40 ServiceMonitors + 145 alertas já configurados
- **Impacto:** -70% esforço real vs planejado (9h → ~3h total estimado)

### 2. Alertas genéricos vs SLI-specific
- **Descoberta:** Alertas existentes são infrastructure-focused (nodes, pods, cluster)
- **Gap:** Falta application-level SLI alerting (latency, error rate per service)
- **Fix:** PrometheusRule custom para Golden Signals

### 3. ServiceMonitor ≠ SLI alerting
- **Confusão inicial:** 40 ServiceMonitors deveriam cobrir alertas
- **Realidade:** ServiceMonitors = metric collection, não automated alerting
- **Ação:** Criar alertas explícitos baseados nos metrics coletados

## Bloqueios e Resoluções

### Bloqueio 1: Falta de metrics HTTP personalizados

**Problema:** Nem todos os serviços expõem `http_request_duration_seconds_bucket` (histograms)

**Serviços afetados:**
- GitLab: ✅ Expõe (gitlab_transaction_duration_seconds)
- Harbor: ✅ Expõe (harbor_registry_http_request_duration_seconds)
- ArgoCD: ⚠️ Métricas básicas, precisa validar histograms
- Vault: ⚠️ Métricas básicas, precisa validar histograms
- Keycloak: ⚠️ Métricas básicas, precisa validar histograms

**Resolução:**
- **Opção A:** Validar metrics existentes com `kubectl port-forward` + curl `/metrics`
- **Opção B:** Adicionar instrumentation via ServiceMonitor relabel configs
- **Opção C:** Usar Tempo traces como fallback (distributed tracing já operacional)

**Decisão:** Postergar para Fase 3 (Dashboards), usar Tempo traces como source of truth

---

### Bloqueio 2: PostgreSQL exporter não instalado

**Problema:** Alertas PostgreSQL requerem `postgres_exporter`

**Status atual:** RDS PostgreSQL não tem exporter Prometheus configurado

**Resolução:**
- **Opção A:** Instalar postgres_exporter via Helm (requer connection string)
- **Opção B:** Usar CloudWatch metrics via CloudWatch Exporter (já instalado?)
- **Opção C:** Postergar PostgreSQL alerts para Sprint 4 (não crítico para staging)

**Decisão:** Opção C - Postergar, focar em application-level SLIs primeiro
